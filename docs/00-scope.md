# PIXEL MART scope

## 鎖定
- 教學流程 = `value/` 原版（對貨 + 櫃檯付足）
- 操作 = 大掣／點圖，唔使十字走位
- 比錢 = 符號三選，唔數銀（**金額只係讀出嚟，唔使學生心算**）
- 三個 mode 共用同一條流程骨：**門口 → 貨架 → 核對 → 對貨 → 櫃檯三選 → 結果 → 證狀**
- **三個 mode 全部喺「對貨」之後加兩步**：掃描商品 → 拍卡付款 → 收據
  （小學要求 4「體驗無人商店的購物及電子付款流程」／中學要求 5）
- **三個 mode 開機自動先經課堂引入畫面**（`s-intro`，要求 1；問題數 mode-aware）

## 活動週 2026-11-23～27 路由
| 對象 | mode | 注意 |
|---|---|---|
| 中學形狀（週主推） | `shape` | 封面推介；中卡先；AUTO_WALK on |
| 中學數量 | `secondary` | 即用，唔等 value 教材二 |
| 小學圖片配對 | `primary`（封面新卡「小學·配對」） | 3 張單（初／中／高）；清單用真實相片 ↔ 貨架用 emoji（高卡相反） |

星只獎比足；形錯≠不誠實；禁分類籃冒充誠信。

## 禁止
- open-world 超市
- 多層選單／背包
- 即時 NPC 劇透對錯
- 覆蓋 `sen-unmanned-store` Live
- 自由地圖／數銀／多房（永遠唔做）

## 同步
原版 logic 修好 → diff 進本盤 JS；CSS 皮保留本盤。

## 三個 mode（v1.6 定案）

| Mode | `MODES` key | 清單格式 | 跟單定義 | 星星 |
|---|---|---|---|---|
| 小學·配對 | `primary` | `items: [{id,qty}]` + `pic: "list"｜"name"` | 呢幾樣嘢一樣都冇漏冇多 | ⭐ = 付足 |
| 中學·數 | `secondary` | `items: [{id,qty}, …]` | 每樣數量啱 | ⭐ = 付足 |
| 中學·形 | `shape` | `shapes: [{shape,qty}, …]` | 每種形狀嘅**數量**啱 | 🥈 = 跟單 · ⭐ = 跟單 + 付足 |

`MODES` 嘅 `qty` / `shape` flag 係 mode 開關；`epay: false` 可以令某個 mode 唔使電子付款（現時冇 mode 用）。
邏輯靠 `isPrimaryMode()` / `isQtyMode()` / `isShapeMode()` / `hasEPay()` 分流。

### 小學·配對 設計定案（2026-11-11）
小學課程要求 3 係「能配對商品圖片與實物」→ **必須有兩種唔同呈現先算真正配對**。

| 卡 | 清單呈現 | 貨架呈現 | 配對方向 |
|---|---|---|---|
| 初 | 曲奇**相片** | 🍪 emoji | 相 → 實物 |
| 中 | 朱古力 + 牛奶**相片** | 🍫 🥛 emoji | 相 → 實物 |
| 高 | 曲奇×2 + 飯糰（**名 + 數量**） | 真實**相片** | 名 → 相（相反） |

⚠️ **三處呈現必須一致**（門口卡 / 地圖清單常駐條 / 核對枱清單欄）
—— 任何一處唔同，學生核對時就搵唔到對應嘢 = 「清單常駐」紅線失守。
⚠️ **c2 唔入小學清單** —— c1／c2 嘅 emoji 都係 🍪（配對有歧義）。
⚠️ **小學唔顯示形狀 badge** —— badge 會令任務變成「搵形狀」，而且提前洩漏答案。
⚠️ **小學用 `ITEMS[].sname`**（曲奇／布甸／紙巾／朱古力／豆腐…），唔用中學名。
⚠️ **同一款多件要能累加 + 逐件放返低** —— 高卡曲奇 ×2 佔 2 個架位，
`state.basketSlots[id]` 記每件貨自己嘅架位，`putBack()` 每次只減 1 件。


### 中學·形 設計定案（2026-11-10 改：長方形入單）
（原文註解）
```
數1–5；●▲▬入單；■干擾；供≥需+餘
銀=跟單；金=跟單+比足。形錯≠不誠實。
```

逐句拆：**●▲▬ 入單** = 圓/三角/**長方形**可以出現喺清單 · **■ 干擾** = 正方形只做干擾 ·
**供 ≥ 需 + 餘** = 貨架供應要夠用仲要有多餘 · **銀 = 跟單 / 金 = 跟單 + 比足** ·
**形錯 ≠ 不誠信**。

⚠️ **點解長方形要入單**：中學課程要求 3 寫明「能辨認**圓形、三角形及長方形**物件」。
舊版將長方形做干擾 = 學生永遠唔使認長方形 = **要求 3 做唔到**。
⚠️ **點解正方形改做干擾**：正方形對長方形正正係中度學生最易混淆嗰位
（兩個都係「方」）。留佢做干擾，逼學生真係睇形狀，唔係靠印象。

⚠️ **「數1–5」定案**：每種形狀 qty ∈ 1–5，**且**每單總件數建議 ≤5（中度負荷）。  
現行卡：中總4、高總5；每形 1–2 —— 未頂滿上限，夠活動週用。

**供應表**（貨架 9 個位，`MAP_LAYOUT` row 2/4/6 × x=2,4,6）

⚠️ **2026-11-11 難度調整定案（用戶投訴「相同形狀物件出現，正方形 3 款、三角形 2 款，
難度太高去比較，學生會揀錯」）**：
舊版架上同一形狀擺咗 2–3 款，學生要逐款比較先知邊件啱，仲好容易「多取」→ 跟單失敗。
新定案：**每種清單要嘅形狀，架上只擺清單需要嗰啲件數**（清單要 ●×2 → 架上就係得 2 個圓形），
其餘架位填 **不規則干擾物**（`o1`–`o6`：香蕉／茄子／粟米／西蘭花／魚／襪子）。
→ 每種目標形狀喺架上唯一可辨，學生唔會揀錯形狀。
⚠️ **判分唔放寬**：攞咗不規則干擾物 = 多取 = 跟單失敗（冇星），「忍住手」教學點原封不動。
⚠️ **中卡保留 1 個 ■（s1）干擾**：要求 3 教「分辨正方形 vs 長方形」，
得 1 個正方形對 1 個長方形 → 只比一次，負擔細但教學點仲喺度。
⚠️ **干擾物冇相片**（image gen 喺呢部機唔用得）→ 用 emoji + canvas 白底框，統一同相片嘅外觀。

| 級 | 清單需求 | 貨架供應（2026-11-11 版） | 設計重點 |
|---|---|---|---|
| 中 | ●2 ▲1 ▬1（合共 4 件） | ●2 ▲1 ▬1 ■1 ＋ 不規則 ×4 | 每種形狀件數 = 清單需求；■ 干擾 1 個 |
| 高 | ●2 ▲1 ■1 ▬1（合共 5 件） | ●2 ▲1 ■1 ▬1 ＋ 不規則 ×4 | 每種形狀件數 = 清單需求；零多餘 |

⚠️ 現有資料**每種形狀只用到 1–2 件**，遠未撳到「數1–5」嘅上限。
日後要放大數量，先確認貨架供應夠（`LISTS_SHAPE[].shelf` 加貨要同時加 `assets/shape/` 圖）。

**形狀 ↔ 貨**
| 形狀 | badge | 代表圖 | 貨 |
|---|---|---|---|
| 圓形 | ● | `c1` 餅乾盒 | c1 餅乾盒 · c2 曲奇罐 · c3 布甸杯 |
| 三角形 | ▲ | `t1` 蛋糕盒 | t1 蛋糕盒 · t2 飯糰 |
| 長方形 | ▬ | `r1` 果汁盒 | r1 果汁盒 · r2 牛奶盒（**入單**） |
| 正方形 | ■ | `s1` 紙巾盒 | s1 紙巾盒 · s2 朱古力盒 · s3 豆腐盒（**干擾**，唔入清單） |

清單用 `SHAPE_REP`（每形狀代表一件），唔綁死成單一貨 → 學生見到三款圓形，
要自己認形狀 + 自己數件數。

### 誠信語意（重要）
| 情況 | 判斷 | 星星 | 會唔會記「對貨有落差」 |
|---|---|---|---|
| 跟單 + 比足 | 金 | ⭐ | 唔會 |
| 跟單 + 冇比足 | 銀 | 🥈 | 唔會 |
| 形狀／數量錯 + 比足 | 只講「你有付足」 | — | **唔會**（形錯 ≠ 不誠實） |
| 形狀／數量錯 + 冇比足 | — | — | 唔會 |
| 對貨答「一樣」但實際唔一樣 | 有落差 | — | **會**（唯一嘅誠信問題） |

誠信只由「對貨答覆 vs 實際」決定，**唔由攞錯嘢決定**。

### 誠信語意（中學 mode 加咗拍卡之後）
| 情況 | 結果畫面標題 | 星星 |
|---|---|---|
| 跟單 + 拍卡付足 | 「你有誠信！」 | ⭐ |
| 跟單 + 只畀一半錢 | 「記得要付足」 | — |
| 跟單 + 唔付款就走 | 「攞咗就要付」 | — |
| 對貨答「唔一樣」而實際真係唔一樣 | 「你有誠信！」+ 列出漏咗乜 | ⭐（誠實 ≠ 攞齊） |

⚠️ **拍卡只係令付款變真實，唔係自動扣卡** —— 三個掣保留，因為
「星只獎比足」同「誠信主關」兩條紅線都靠呢個選擇。
⚠️ **誠信仍然只由對貨答覆決定** —— 答「唔一樣」而實際真係唔一樣 = 誠信（冇星唔代表唔誠信，
可能只係未付足）。

## 陷阱（加新 mode 前必讀）

### `listIds()` 喺唔同 mode 回傳唔同嘢
```js
function listIds(list){
  if(list.shapes) return list.shapes.map(s => s.shape);   // ← 形狀名，唔係 item id！
  return list.items.map(i => typeof i === "string" ? i : i.id);
}
```
形狀 mode 回傳 `"circle"` / `"triangle"` / `"square"`。任何假設 `listIds()` 一定係 item id
嘅地方，喺形狀 mode 會攞到 `ITEMS["circle"]` → `undefined` → 讀 `.name` 就死機。

**呢個就係 v1.7 修嘅 crash**（形狀 mode 一入地圖 100% 死）：
```js
// renderMap() 錯版
const ids = listIds(L).concat(shelfIds(L));
// renderMap() 修版
const ids = isShapeMode() ? shelfIds(L) : listIds(L).concat(shelfIds(L));
```
（形狀 mode 全部實物都喺貨架，清單只描述形狀 → 淨係擺 `shelfIds()`。）

**守則**：加新 mode 嗰陣，`listIds()` 嘅**每個 call site** 都要重新睇一遍
（而家只有 `renderMap()` 一處會喺形狀 mode 出事；`renderDoor` / `renderListStrip` /
`renderCheck` / `answerCheck` / `judge` 全部喺 shape 分支跳過）。

### 未知 item id 唔好炸成個畫面
`ITEMS[id]` 可能係 `undefined`。直接寫 `ITEMS[id].name` 會令成個地圖 render 死機，
之後所有嘢都撳唔到。v1.7 改成 `const it = ITEMS[id]; it ? … : "貨架"`。

### 切 mode 要清晒 state
`setMode()` 要清 `basket` / `basketN` / `checks` / `cursor` / `declared` / `declareAns` /
`paid` / `payChoice` / `silvers` / **`stars`** / **`log`**。
（v1.7 補咗 `stars` + `log` —— 之前只清 `silvers`。）

### 唔寫 localStorage / sessionStorage
防止上一個學生嘅資料污染下一個學生。老師記錄面板只存記憶體，老師手動複製走。

### 改清單格式 = 必查判分層（v1.9 血痕）
長方形正式入單之後，`shapeMatchInfo()` 仲係寫住「攞咗 rect 就當多取」→
**跟單啱都判成錯**，派唔到金星。code review 完全睇唔出（改資料層唔會自動改判分層）。
⇒ **清單格式一改，就即刻搵出所有會讀清單／形狀嘅函式，逐個對**。

### `hidden` 屬性唔係萬能
只要 CSS 寫咗 `display`（例如 `display:flex`），HTML `hidden` 就會**完全失效**。
v1.9 收據彈唔出、掃描步驟唔收埋，就係咁嚟。
⇒ 全局加 `[hidden]{ display:none !important; }`。

### 籃唔好撐高過視窗
籃內每件貨掛 30px 形狀 badge → 籃撐高 `#bottombar` → 頂部「清單常駐」條被切走
= **踩教學紅線**（清單必須常駐）。
⇒ 籃內唔掛 badge（caption 已經有數字）、相縮細、`.items` 加 `max-height`。

### 落單之後要清籃
`nextList()` 跳門口畫面時籃未清 → 學生見到上一單嘅貨 + 「放返低」掣按落冇反應。
⇒ `nextList()` 入面清 `basket` / `basketN` / `basketFrom` + `renderBasket()`。

### 同一個 render 函式唔可以同時「重繪」同「寫提示」
`renderOrderSlots()` 每次都會覆蓋 `#orderHint`。答錯時如果先寫提示、後 `renderOrderSlots()`，
提示會喺同一個 tick 被洗走 → **學生永遠睇唔到「次序未啱」**（靜靜失效）。
⇒ **提示一定要寫喺 render 函式之後**。

### 清單呈現要三處一致
門口卡 / 地圖清單常駐條 / 核對枱清單欄，任何一處唔同，學生就對唔上。
⇒ 統一由清單嘅 `pic` flag 決定呈現（`"list"` = 相片 / `"name"` = 名 + 數量），
三處共用同一個 helper，唔好各自寫。

### 同一款多件要記低每件貨嘅架位
清單可以要求同一款 ×2（高卡曲奇 ×2）→ 架上要佔 2 格，放返低要放返去對應嗰格。
⇒ `state.basketSlots[id]` 存每件貨嘅架位 index；`putBack()` 每次只減 1 件。

### 干擾物 `shape:null` → 形狀計數會漏算（2026-11-11 新增）
形狀 mode 嘅干擾物（`o1`–`o6`）刻意用 `shape:null`（唔屬於 ●▲■▬），
但 `basketShapeCounts()` 係 `if(!sh) return;` —— **會完全跳過佢**。
⇒ 學生攞咗干擾物（香蕉／粟米…），形狀數量全部啱，仍然會判成「跟單成功」→ 直接派埋金鍾，
   「忍住手唔好多取」呢個核心教學點就爆咗。
⇒ 必須另外計：`basketOddIds()` / `basketOddCount()`（行 `ITEMS[id].odd` 旗標），
   `shapeMatchInfo()` 入面 `oddN > 0` → `mathOk = false` + `tookExtra = true`。
⚠️ **通則：任何「唔屬於主類別」嘅干擾項，都唔可以靠主類別嘅計數函式去偵測**，
   否則個干擾項就係「隱形」—— 系統會當佢唔存在。
⚠️ 對應嘅呈現位（籃度 caption、掃描兩欄、老師記錄、結果句子）都要跟住顯示干擾物，
   否則學生會見到籃度有嘢但 caption 唔講、老師亦唔知多咗咩。
